# Security notes

| Boundary | Implemented behavior | Limit / remaining work |
| --- | --- | --- |
| HTTP bearer auth | When configured, one UUIDv4 credential is created per opened session and sent to the agent for its exact MCP endpoint. Only `POST /mcp/<decoded-thread>` uses this credential; the admin bearer does not authorize MCP. Failed/cancelled opening revokes its provisional credential; session removal revokes the live credential, and replacement/reopening rotates it. Normal `POST /session/cancel` cancels a turn but keeps the live session credential. Other protected routes still require the admin bearer. | Origin checks remain independent. With auth unconfigured, existing unauthenticated mode remains. This is least-privilege HTTP access, not an OS sandbox against a same-user agent. |
| ACP subprocess environment | Known bridge-token variables are blanked for the child environment. | Vendor API credentials remain available to the agent. |
| Subprocess cleanup | The guarded transport connection owns child cleanup. On Unix it kills the process group before falling back to the child; other platforms fall back to the direct child. | The CLI's Linux-only `/proc` sweep is best effort. It cannot run after forced bridge termination. |
| Filesystem root | `canonicalize_cwd` returns a path without permanently retaining a directory handle. `pin_filesystem_root(&Path)` returns `std::io::Result<FilesystemRootGuard>`; keep the guard alive across related operations to preserve directory identity. Actors pin their canonical internal root while retaining the original wire cwd. Per-operation leases protect suspended I/O; expired weak-cache entries are pruned. | Secure filesystem operations fail closed off Linux. This is not a general OS sandbox. |
| Stream ingress | ACP frames and queued wire data are limited to 16 MiB each, with at most 4,096 queued entries; batches count their entries. The SDK parser/serializer is retained, and violations fail closed. | Serialized-wire budgets are not exact heap or global process-memory guarantees. |
| Turn delivery | The event mailbox admits at most 4,096 outstanding data items and 16 MiB of serialized payload. Credits remain held during downstream sends. One reserved terminal position and a delivery acknowledgement preserve FIFO order between turns. An overflowing turn fails explicitly and has a finite cleanup deadline. | Zero-timeout mode waits indefinitely only while the actor remains live. Retired SSE streams share one absolute two-second drain deadline; expiration releases run ownership without manufacturing a successful terminal event. |
| Deferred permissions | Admission is limited to 128 pending requests per turn, 64 KiB per request and 16 MiB of reserved payload. Reservations cover policy evaluation until resolution or cleanup. | Resource rejection must not be presented as a successful permission decision. |
| Spawned filesystem and terminal work | Seven spawned request lanes share a per-connection budget of 128 requests and 16 MiB of serialized request/ID data. Blocking operations retain credit until they actually finish, even when the async waiter is cancelled. Exhaustion retires the connection with an explicit quota error. | This bounds admitted work and retained request data, not all memory used by subprocesses or the runtime. |
| Frontend dependencies | Braces 3.0.3 is locally patched and pinned through tracked patch metadata; frozen install is reproducible. The patch addresses parser depth and iterative AST traversal. Undici 6.29's root override affects only two old `@ai-sdk/provider-utils` 3.0.41 branches under Google Vertex and OpenAI-compatible integrations; `@ai-sdk/provider-utils` 4.0.57+ and OpenAI peer-compatible 6 are unchanged. UUID 11.1.1 is applied by root override; Mermaid's declared union range allows it, while an unused runtime 10 branch crosses that range. | Upstream braces GHSA-vfj7-8cjw-p6xm remains reported HIGH despite the locally accepted mitigation. DNS/private/mixed-address and UUID validation are complete; no UUID, Undici, or Busboy advisories remain. |

Do not treat bearer authentication as process isolation: a same-user agent has
the privileges of its operating-system account. Keep credentials and filesystem
permissions appropriate to that trust boundary.
